# 權限驗證簡要說明（admin / operator / viewer）

本文檔說明系統中三種內建角色的**能力範圍與驗證方式**，協助快速確認權限是否設定正確。

---

## 一、角色能力總表

| 能力／功能                                       | admin            | operator         | viewer                  |
| ------------------------------------------------ | ---------------- | ---------------- | ----------------------- |
| 登入、取得自己的用戶資訊（含 `permissions`）    | ✅               | ✅               | ✅                      |
| **用戶管理**（列表、新增、編輯、刪除、權限設定） | ✅               | ✅               | ❌                      |
| **設備管理**（類型 / 型號 / 設備 CRUD）         | ✅               | ✅               | ❌                      |
| **警報**（規則 CRUD、忽略）                      | ✅               | ❌（僅可看列表） | ❌（僅可看列表）        |
| **授權**（license 啟用）                         | ✅               | ❌               | ❌                      |
| **系統設定**（key-value 寫入）                   | ✅               | ❌               | ❌                      |
| **人員管理**（人員 / 群組 / 門禁權限寫入）       | ✅               | ✅               | ❌                      |
| **門禁**（設備設定與寫入）                       | ✅               | ✅               | ❌                      |
| **地點管理**（全區點位圖入口、區域管理按鈕）     | ✅（預設有）     | ✅（預設有）     | ⚠️ 依覆寫權限（預設無） |
| 更多功能選單（設備管理、全區點位圖、人員管理）   | ✅ 全部          | ✅ 依權限顯示    | ❌ 不顯示               |
| 環境／人流／車輛／照明等「僅需登入」的讀取       | ✅               | ✅               | ✅                      |
| 照明開關、環境／車輛等寫入或操作                 | ✅（isOperator） | ✅               | ❌                      |

### 系統設定（僅 admin 可寫）

- 後端以 `system_settings` 表保存站名、Logo、區域圖等 key-value 設定。  
- **讀取**（GET 全部 / 單一 / 批次）只需登入；**寫入**一律需 admin：
  - `PUT /api/settings/:key`：更新單一 key
  - `POST /api/settings/upload`：上傳檔案並更新某 key 為檔案路徑
  - `DELETE /api/settings/:key`：刪除 key（若為檔案路徑則一併刪檔）

## 二、admin（管理員）驗證重點

**目標：確認 admin 具備所有管理與設定能力。**

- **登入與首頁**
  - 登入成功後，`user.permissions` 應包含所有定義的權限。
  - 能看到完整首頁與設定圖示。

- **用戶與設備管理**
  - 可進 `/core/users`，執行：新增、編輯、刪除其他用戶、開啟「權限」對話框並儲存。
  - 可進 `/core/equipment-management`，對「類型 / 型號 / 設備」做 CRUD，後端應全部接受。

- **警報、授權、系統設定**
  - 警示紀錄頁可忽略警報、對規則做新增 / 編輯 / 刪除。
  - 若有 license 頁，admin 可成功啟用授權。
  - 系統設定相關 API（單筆更新、上傳、刪除）皆可成功寫入。

- **地點 / 人員 / 門禁**
  - 「更多功能」中可看到「全區點位圖」「人員管理」等入口。
  - 全區點位圖頁中，應顯示「區域管理」按鈕，且可新增 / 編輯 區域與地點。
  - 人員管理與門禁相關操作（寫入 / 設定）應由後端接受。

---

## 三、operator（操作員）驗證重點

**目標：確認 operator 具備日常操作能力，但無系統級設定與授權。**

- **登入與導航**
  - 登入成功後，`user.permissions` 至少包含：
    - 用戶 / 設備 / 人員 / 門禁相關寫入
    - `operation.location_management`（可管理地點）
  - 底部導航有「更多功能」九宮格與設定圖示；設定下拉可看到「用戶管理」「登出」。

- **用戶 / 設備管理（與 admin 同級）**
  - `/core/users`：可列表、新增、編輯、刪除其他用戶、開啟「權限」對話框並儲存。
  - `/core/equipment-management`：可對類型 / 型號 / 設備做 CRUD。

- **警報、授權、系統設定（應受限）**
  - 警示紀錄：可看列表；忽略 / 規則 CRUD 若後端維持 `requireAdmin`，應得到 403。
  - 授權啟用 API、系統設定寫入（更新 / 上傳 / 刪除）皆應得到 403。

- **地點 / 人員 / 門禁**
  - 「更多功能」中可進入「全區點位圖」，頁面上應顯示「區域管理」按鈕，可編輯區域與地點。
  - 「人員管理」頁面可新增 / 編輯 / 刪除人員與門禁相關資料。
  - 門禁設備或設定寫入由後端 `requireAdminOrOperator` 驗證，operator 應可成功。

---

## 四、viewer（檢視者）驗證重點

**目標：確認 viewer 僅能瀏覽，無任何管理或寫入能力。**

- **登入與導航**
  - 登入成功後，`user.permissions` 僅包含預設唯讀權限（例如即時預覽、播放、`operation.monitoring`）。
  - 底部導航**沒有**「更多功能」按鈕。
  - 設定下拉選單**沒有**「用戶管理」，只保留「登出」。

- **用戶與地點管理限制**
  - 直接打 `/core/users`：頁面可能載入，但 `GET /api/users` 應回傳 403，列表載入失敗。
  - 「更多功能」按鈕不存在，因此無法從 UI 進「全區點位圖」。
  - 若直接打 `/core/area-point-map`：
    - 頁面可開啟，但 `hasPermission('operation.location_management')` 為 `false` 時，「區域管理」按鈕不顯示。
    - 只能瀏覽既有區域 / 地點，無法新增 / 編輯 / 刪除。

- **其他系統（僅讀或依 license）**
  - 首頁、環境、人流、車輛、照明等頁面可進入並瀏覽（依 license 開啟與否）。
  - 任何寫入或操作按鈕要嘛不顯示，要嘛送出 API 後被後端拒絕。
  - 設備管理、人員管理頁面如直接打網址，相關寫入 API 應回傳 403。

- **viewer 被覆寫「地點管理」權限時**
  - 由 admin / operator 在「權限」對話框勾選 viewer 的「地點管理」並儲存後：
    - 該 viewer 重新登入或重新呼叫 `/me` 時，`user.permissions` 中應有 `operation.location_management`。
    - 若未來 UI 允許 viewer 顯示「更多功能」，「全區點位圖」與「區域管理」顯示與否應僅依 `hasPermission` 判斷。
    - 目前設計下，若 viewer 直接打 `/core/area-point-map`，已有上述權限時「區域管理」按鈕應顯示。

## 五、最小驗證清單（依角色）

- **admin**
  - ☐ `/core/users` 可完整 CRUD 用戶與權限  
  - ☐ `/core/equipment-management` 可完整 CRUD 設備  
  - ☐ 警報規則 / 忽略、授權啟用、系統設定寫入皆可成功  
  - ☐ 可進人員管理、門禁、全區點位圖並顯示「區域管理」

- **operator**  
  - ☐ `/core/users`、設備管理與 admin 同級 CRUD 能力  
  - ☐ 警報規則 / 忽略、授權、系統設定寫入一律 403  
  - ☐ 可進人員管理、門禁、全區點位圖並顯示「區域管理」  

- **viewer**
  - ☐ 設定選單無「用戶管理」，UI 無「更多功能」選單  
  - ☐ `/core/users` 列表 API 回傳 403  
  - ☐ `/core/area-point-map` 預設不顯示「區域管理」按鈕（除非已覆寫權限）  
  - ☐ 僅能瀏覽首頁與依 license 開放的唯讀頁面，所有寫入皆被拒絕

## 六、實作與驗證說明

- **權限來源**：實際可用權限來自後端 `permission_definitions`、`role_default_permissions`、`user_permission_overrides` 綜合計算，登入與 `/me` 回傳的 `permissions` 即為最終結果。  
- **前端判斷**：
  - 用戶管理入口與操作欄：依 `canManageUsers`（`isAdmin || isOperator`）。  
  - 「全區點位圖」選單與「區域管理」按鈕：依 `hasPermission('operation.location_management')`，admin 視為必定擁有。  
- **後端保護**：
  - 用戶相關 API、設備 CRUD、人員、門禁：`requireAdminOrOperator`。  
  - 警報規則 / 忽略、授權啟用、系統設定寫入：`requireAdmin`。  
- 建議以 **admin / operator / viewer 三種帳號各跑一次上述最小清單**，逐項勾選確認即完成整體權限驗證。
